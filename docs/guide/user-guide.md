# 管理台使用教程

本文说明从空管理台配置到第一条测试消息的流程。导航中的“会话管理”和“群聊策略”职责不同：会话管理操作已保存策略对应的运行状态；群聊策略决定该会话使用的供应商、模型、提示词、白名单和预算。

## 推荐配置顺序

管理台左侧导航已经按这个顺序排列。照着做就能跑通第一条消息：

1. **接口能力 → AI供应商**：填写兼容 API 地址、密钥和模型。
2. **接口能力 → 单价**：导入预置单价或按实际账单登记，预算按这里计算。
3. **接口能力 → 身份**：创建身份策略，选择模型、系统提示词和可用工具。
4. **插件管理 / 平台账号**：确认群聊助手插件，然后填写 QQ AppID 与 AppSecret。
5. **群聊策略**：选择账号、填写群 openid，再选择身份策略；其余留空即继承。
6. **会话管理 / 对话日志**：在群里 @ 机器人，检查连接状态和错误日志。

“群聊策略”只负责把账号、会话 ID 和身份策略关联起来。模型、系统提示词、Skills/MCP/Rules 等共享配置放在身份策略里，不需要在每个群重复填写；群聊表单的“05 / 高级设置”可以全部留空。

## 配置前准备

1. 部署并初始化持久化存储，设置 `SYS_PASSWD` 与 `SYS_SECRET`。
2. 准备 QQ 机器人 AppID、AppSecret，以及 QQ 开放平台回调配置。
3. 准备兼容项目请求格式的 AI API 地址和密钥。若使用 MCP，再准备其地址、认证信息和管理员审查过的工具 allowlist。
4. 确认要测试的群聊/私聊 OpenID。会话管理列表由保存的会话策略生成，不会自动扫描或导入历史聊天。

## 第一次配置

### 1. 登录管理台

打开部署域名的管理入口，用 `SYS_PASSWD` 登录。管理 API 需要有效管理员 session；首次使用时按部署页说明完成数据库初始化。

### 2. 配置 AI 供应商与单价

在“接口能力 → AI供应商”中填写供应商名称、兼容 API 地址、API Key 和模型信息。再到“单价”导入常用模型预置，或按实际账单登记输入、输出价格和计价单位。价格配置参与预算计算；没有登记单价的文本模型按默认 $3 输入 / $15 输出每百万 token 计费，不再拒绝执行。

媒体能力按具体供应商与模型登记。未声明支持的附件不会假装已读；外部请求和账单仍由供应商负责。

### 3. 创建身份策略

在“接口能力 → 身份”新建策略，选择供应商与模型，填写系统提示词，并按需勾选 Skills、MCP、Rules。身份策略是群聊共享的默认值：一个群聊只引用它，不必重复填写模型和工具。没有身份策略时，群聊也可以直接覆盖模型和提示词，但不利于多个群复用。

### 4. 确认插件

在“插件管理”确认群聊助手（`elysia-best/plugin-chatbot`）已注册并启用。插件字段会根据项目声明的字段类型渲染；密钥字段不会以普通文本回显。不要把 JSON、账号密钥或供应商令牌贴进非密钥字段。

### 5. 添加 QQ 平台账号

在“平台账号”中创建 QQ 账号，选择群聊助手插件，并填写 QQ AppID、AppSecret。密钥由服务端使用 `SYS_SECRET` 加密存储；更换 `SYS_SECRET` 前需考虑已有密文的解密兼容。

### 6. 添加群聊或私聊策略

在“群聊策略”中选择上一步账号，填写外部会话 ID/OpenID 和会话类型，然后按表单顺序配置：

- **01 / 基本信息**：账号、会话 ID、管理员 ID、名称与启用状态；
- **02 / AI 与提示词**：选择身份策略；需要不同角色时填写人设或本会话提示词；覆盖项留空时继承身份策略；
- **03 / 费用限额**：每日、每月和总限额，0 表示不设限；
- **04 / 能力扩展**：在身份策略之上追加 Skills、MCP、Rules；
- **05 / 高级设置**：仅在需要对话/语音策略、用户白名单、预留模式或自定义时区时展开。

每个会话还可以在“02 / AI 与提示词”的**人设**中填写角色设定。人设描述身份、语气和表达习惯，会排在身份策略/系统规则之前；角色卡、会话记忆、Skills/Rules 和模式指令再由运行时依次追加。不要把权限规则写进人设，也不要把密钥或隐私写进提示词。

只为自己有权管理的会话创建策略。群 OpenID 与用户 OpenID 属不同范围，不要混填。

### 7. 验证收发

确保 QQ 回调指向 `/webhook/qq`、签名相关请求头和原始 JSON body 未被代理修改。使用白名单内的测试账号，在绑定会话中发送消息。通过 `/help` 查看命令；`/openid` 可用于核对当前用户与群聊 OpenID。不要在公开群中发送密钥或隐私数据。

## 会话管理与运行命令

“会话管理”可按已有策略查看状态，设置运行模式、静默、一次性提示和额外禁用工具，重置上下文，并处理待审批工具、计划唤醒和素材。策略列表为空时，先检查平台账号、群聊策略和有效 OpenID；它不是聊天历史查询页。

常用命令（权限以会话策略和身份为准）：

| 命令 | 用途 |
| --- | --- |
| `/help` | 查看当前身份可用的命令 |
| `/status` | 查看会话运行信息 |
| `/reset` | 重置会话上下文 |
| `/mode` | 管理运行模式 |
| `/role` | 管理会话角色卡 |
| `/memory` | 管理当前会话记忆 |
| `/openid` | 查看当前用户与群聊 OpenID |
| `/approvals`、`/approval`、`/approve`、`/reject` | 查看、批准或拒绝待审批工具调用 |
| `/wake` | 查看或取消持久化计划唤醒（平台能力适用时） |
| `/tools` | 在策略既有权限范围内额外禁用工具 |

对于 MCP 工具，远端 `readOnlyHint` 不构成信任证明。只有管理员 allowlist 与远端只读标记同时满足时才可直接运行；其他可用调用进入 owner 审批流程。管理台的“待审批操作”支持先编辑参数再批准：保存只修改待审批调用，不会执行工具，仍须 owner 显式批准；参数必须是 JSON 对象，且不能包含密钥。

## 角色卡与记忆

会话角色卡使用 `/role` 命令或管理台维护。账号共享角色卡和项目记忆与当前会话记忆是不同作用域；共享数据不会自动变成任意会话的写权限。`MemoryWrite` / `MemoryForget`、共享写入与删除都有 owner 限制。

在开放记忆或 MCP 前，先确认参与者、数据范围和保留时长。模型输出、联网搜索结果、Skills/Rules 和外部文档都应当作为不可信内容处理。

## 日志与隐私

`LOG_RECORD` 默认关闭。启用后会记录用户/会话标识、消息内容、模型/工具状态、用量和错误；有效期最多 30 天，并需要配置定时物理清理。参见[日志保留与清理](/operations/log-retention)。不要将凭据或敏感隐私放进提示词、群聊或日志。

## 常见问题

- **会话列表为空**：检查是否已有平台账号、已保存群聊/私聊策略及有效 OpenID；仅配置账号不会发现聊天记录。
- **模型请求失败**：核对 API 地址、密钥、模型 ID、媒体能力声明及供应商额度；检查部署日志时不要泄露密钥。
- **回复未发送**：核对 QQ 回调签名、账号启用状态、会话 OpenID、白名单与平台发送权限。
- **工具等待审批**：在管理台检查工具名称和参数，再由 owner 决定批准或拒绝；不要仅凭工具自报只读就批准。
- **成本字段缺失或拒绝调用**：检查对应模型和计价单位的有效单价，以及会话预算。
